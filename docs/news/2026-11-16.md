# Fluid editor · Monday 16 November 2026

14 pull requests merged. None changed the editor. Twelve made a check harder to fool, one steadied a typing row that went red by chance, and one started this News. A check runs our editor through recorded steps and compares it with what Squarespace's real editor, the oracle, was seen to do. Most pull requests prove their point the same way: break the editor, or the recorded oracle data, on purpose in a scratch copy, then show the old check still passes and the new one fails.

## What a person can now do

Nothing new to click today. What changed is how much the checks hold the editor to. To read a check's verdict, open `parity/snap-check.json`: it comes from a real run, where all 264 rows pass.

**Snapping blocks.** The snap check drags a block and compares each pixel step with the oracle.

- It used to skip the first step of a leg whenever that step sat on the start area, which also skipped five real returns home ([#681](https://github.com/FRIKKern/fluid-editor/pull/681)). With a block forced to come home 20 px late, the old check passed 179 of 188 rows and the new one fails three more.
- Walks along the margins now also come home (28 new rows, [#683](https://github.com/FRIKKern/fluid-editor/pull/683)) and walk up and down, as the oracle did (216 to 252 rows, [#685](https://github.com/FRIKKern/fluid-editor/pull/685)). A phone block's up-and-down snap was compared nowhere in the snap check before.
- The right-margin move and corner resize are compared too (252 to 264 rows, [#686](https://github.com/FRIKKern/fluid-editor/pull/686)). A block forced 10 px late from the right edge now fails 3 rows.

**Typing, undo and Save.** Replays of recorded typing now also compare whether Save is on and which page the editor is on ([#680](https://github.com/FRIKKern/fluid-editor/pull/680), [#689](https://github.com/FRIKKern/fluid-editor/pull/689)). A fresh page now starts saved, so only the steps can turn Save on ([#687](https://github.com/FRIKKern/fluid-editor/pull/687)). An undo walk compares where it stops and how many presses it took (40 reads, [#688](https://github.com/FRIKKern/fluid-editor/pull/688)). Known misses may differ only by a set amount, such as one row ([#690](https://github.com/FRIKKern/fluid-editor/pull/690)).

**Style panel.** The Shuffle rows took their expected values from the same table the app shuffles from, so a wrong table passed ([#678](https://github.com/FRIKKern/fluid-editor/pull/678)). They now come from the oracle's captures, and match that table on all nine tiles. A Shuffle that stopped setting Wave, Blur, Bevel, Animate or Morph now fails ([#684](https://github.com/FRIKKern/fluid-editor/pull/684)). The Layouts closing row checked "nothing selected" with a mark no app file has; now it reads the app's own selection marks ([#677](https://github.com/FRIKKern/fluid-editor/pull/677)).

## Where it is slow or rough

- **One real gap.** Add a Text block, write in it, press Undo. The block is gone and our page is back as loaded, so our Save turns off. Squarespace keeps Save on. Only that row's Save part is excused for now ([#687](https://github.com/FRIKKern/fluid-editor/pull/687)).
- On the macOS runner, timers can fire late (a 500 ms timer at up to 648 ms). One typing row waited 900 ms and sometimes landed past the 1,000 ms split, so it went red once, 984 of 985. It now measures the gap it typed ([#679](https://github.com/FRIKKern/fluid-editor/pull/679)).

## Where this fits

Milestone M5 on the [roadmap](../ROADMAP.md) is "it looks like the real editor". The checks decide when that is true, so a check that cannot fail makes the "1:1" number too kind. Monday added nothing to the editor; it turned rows that could not fail into rows that do, and found one real gap on the way.
