# Fluid editor · Sunday 15 November 2026

23 pull requests merged. Two changed the editor; 21 were about the checks, most of them making a check harder to fool.

A word first. The fluid editor copies Squarespace's Fluid Engine editor 1:1. The **oracle** is a real Squarespace trial site we watch; we never copy its code. A **check** is a script that runs our editor through steps recorded on the oracle and compares, row by row. A check is only worth something if it fails when the editor is wrong, and Sunday was about finding rows that could not fail.

## The editor

- **Text bar** ([#657](https://github.com/FRIKKern/fluid-editor/pull/657)). With the Text Alignment, Style or Color menu open, Bold, Italic and Underline used to keep the state they had before. Bold could read "off" over text you had just made bold. Now they follow Cmd+B, Cmd+I and the selection while the menu stays open. 7 new check rows.
- **Message box** ([#659](https://github.com/FRIKKern/fluid-editor/pull/659)). The same in a form's Message box. Also, an Underline waiting at the caret was not let go when the caret moved, so it stayed lit after the menu closed.

## Checks that could not fail

Each of these passed on a wrong editor. Several PRs prove it by breaking the app on purpose: main's check passed, the new one fails.

- Six rows tested a list with "every item is right", which is true for an empty list ([#654](https://github.com/FRIKKern/fluid-editor/pull/654)).
- Three "one undo step" rows (map, video, code) checked only that the last change went back, so an undo that took back two changes passed ([#674](https://github.com/FRIKKern/fluid-editor/pull/674)).
- A line chart that drew no labels passed; now it needs its 3 ([#672](https://github.com/FRIKKern/fluid-editor/pull/672)).
- Site Styles' Cancel was tried at the value Reset gives anyway, so a Cancel that reset passed ([#673](https://github.com/FRIKKern/fluid-editor/pull/673)).
- A Page Link dialog with no page rows passed; now the oracle's first 4 rows are always compared ([#670](https://github.com/FRIKKern/fluid-editor/pull/670)).
- A phone row ran while the shape was pinned, which already shows all 9 buttons, so it said the same as the row above it ([#666](https://github.com/FRIKKern/fluid-editor/pull/666)).
- More of the same in the marks, snap, text and image checks: [#655](https://github.com/FRIKKern/fluid-editor/pull/655), [#658](https://github.com/FRIKKern/fluid-editor/pull/658), [#660](https://github.com/FRIKKern/fluid-editor/pull/660), [#661](https://github.com/FRIKKern/fluid-editor/pull/661), [#662](https://github.com/FRIKKern/fluid-editor/pull/662), [#664](https://github.com/FRIKKern/fluid-editor/pull/664), [#667](https://github.com/FRIKKern/fluid-editor/pull/667), [#671](https://github.com/FRIKKern/fluid-editor/pull/671), [#675](https://github.com/FRIKKern/fluid-editor/pull/675), [#676](https://github.com/FRIKKern/fluid-editor/pull/676).

## Where it was slow: timing on macOS

The marks check measures fades and tooltip delays, and on GitHub's macOS runner it kept missing ([#665](https://github.com/FRIKKern/fluid-editor/pull/665)). The runner batches timers to save power. A probe read:

| macOS runner | frames a second, idle | frames in a 0.2 s fade | a 500 ms timer fired at |
|---|---|---|---|
| as it comes | 19 to 28 | 1 to 5 | 505 to 648 ms |
| timer batching off | 62 | 11 | 501 to 507 ms |
| Linux, for comparison | 62 | 11 | 500 ms |

So the macOS job now turns timer batching off before it starts Chrome, and the check runs on both. The fade rows now judge each frame against the 0.2 s ease-in-out curve at the time it was drawn, instead of hoping one frame lands near the middle ([#668](https://github.com/FRIKKern/fluid-editor/pull/668)); a fade with no middle frames fails ([#669](https://github.com/FRIKKern/fluid-editor/pull/669)).

Two rule changes in `QUALITY.md`: a lowered browser-check count turns main red after merge, because PRs do not run the browser checks ([#656](https://github.com/FRIKKern/fluid-editor/pull/656)), and one Linux text sample's dropped rows show only in the full run ([#663](https://github.com/FRIKKern/fluid-editor/pull/663)).

## Where this fits

Milestone M5 on the [roadmap](../ROADMAP.md) is "it looks like the real editor": toolbars, menus and block types match. These checks are what decide that, so Sunday added no new block but made the numbers behind "1:1" more honest.
