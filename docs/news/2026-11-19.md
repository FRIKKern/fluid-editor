# Fluid editor · Thursday 19 November 2026

11 pull requests merged, one of them Wednesday's News ([#726](https://github.com/FRIKKern/fluid-editor/pull/726)). A check runs our editor through recorded steps and compares it with what Squarespace's real editor, the oracle, was seen to do. One pull request changed the editor. Four made Gate C, the replay of recorded gestures, harder to fool. Three made another check harder to fool, one stopped a check from failing a correct editor, and one read three known misses again on the new trial.

## What a person can now do

Run `npm run dev` and open the editor on a desktop-width window.

**Widen a long Text block** ([#730](https://github.com/FRIKKern/fluid-editor/pull/730)). Take a Text block with several lines of text and drag its edge wider in one drag. At the drop, the oracle keeps the block's rows at some end lines and drops to fewer rows at others. Ours dropped to fewer rows at every end line. Now ours uses the same rule as the oracle for a Text of any number of lines; before, that rule held only for a one-line Text. When you let go, the block takes the rows its text needs, as before.

This was a fresh round: the rule's predictions were pushed before the oracle was read, and both reads agreed on every case. The rule matched 12 of 12; ours before matched 8 of 12. mid-check, the check for what blocks show while a drag or resize is held, passes 1,277 of 1,283 with 6 named known misses (main stored 1,276 with 7): R2 wider 5 is no longer a known miss.

On a phone the same round said no: the rule matched 4 of 6, while the one-line test ours already had matched 6 of 6. A phone keeps the one-line test, and R2 phone wider 2 stays a known miss.

## Gate C, the replay of recorded gestures

Gate C replays each recorded oracle gesture (a drag, a move) on our editor and compares the page it leaves with the oracle's. Each fix below is proved on a scratch build with a fault forced on purpose: the old replay passes it, the new one fails it. Unforced, Gate C still passes 23 of 23, with 23 of 23 undos. Gate C runs locally only, not in CI.

- **A block only ours has** ([#724](https://github.com/FRIKKern/fluid-editor/pull/724)). The compare walked only the oracle's blocks, so an extra block in ours was never read. Now each one is a diff.
- **A copy with the same id** ([#732](https://github.com/FRIKKern/fluid-editor/pull/732)). Two blocks with one id were read as one. Now a repeated id is a diff.
- **A block in another section** ([#733](https://github.com/FRIKKern/fluid-editor/pull/733)). The replay read only the gesture's own section. Now a block left in any other section is a diff.
- **A failed replay exits 1** ([#731](https://github.com/FRIKKern/fluid-editor/pull/731)). The replay printed FAIL but exited 0. Now a failed gesture or undo exits 1, so a script that reads the exit code cannot take a failure as a pass. Nothing reads that code today.

## Checks that got harder to fool

**Outline fades** ([#725](https://github.com/FRIKKern/fluid-editor/pull/725)). After Wednesday's work, a fade frame failed if its outline was hidden, boxless or see-through. Each watched frame now also asks whether the outline is drawn where it is laid out: it must be the topmost element at four points on its border, with nothing on it or its parents making it invisible. Eight more ways to hide it now fail, among them a clip, a filter, a scale to zero, a far move and a cover laid over it. Plain fades and real stalls still pass, also at 4 times slower CPU. No row was added or loosened.

**The drag slot** ([#729](https://github.com/FRIKKern/fluid-editor/pull/729)). While a block is dragged, the oracle draws a slot where it will land. The frames rows scored only the frames where the slot was drawn, so a slot that never came passed. Each row now also reads when the slot shows: always, appears after the start or goes before the end, as the oracle's did. row-check passes 98 of 98, as on main.

**A registry field** ([#728](https://github.com/FRIKKern/fluid-editor/pull/728)). The row "Registry Name is faded and takes nothing" was read on the Design tab, where that field is not drawn, so it passed whatever the field did. It now opens the Content tab and needs the field there and disabled. standin-check, the check for five block types from the add-block menu, passes 213 of 215, as on main.

**The Float row's watch** ([#723](https://github.com/FRIKKern/fluid-editor/pull/723)). This one stops a correct editor from failing. Under load, the setup before a press ate up to 2 s of the row's fixed frame watch, so a correct play ran past its end. The watch now runs to at least 6 s after the click. The timing cases from earlier days still fail as before. anim-check passes 408 of 408 on CI.

**Three known misses read again** ([#727](https://github.com/FRIKKern/fluid-editor/pull/727)). Three of mid-check's named known misses were read twice on the new trial. The oracle does what it did on the old trial, so each miss stays and nothing in the editor changed. The oracle reader can now also read a section's center line.

## Where it is slow or rough

- On a phone, widening a Text in one drag still differs from the oracle; no rule fits both one-step and one-drag widening ([#730](https://github.com/FRIKKern/fluid-editor/pull/730)).
- mid-check still names 6 known misses ([#730](https://github.com/FRIKKern/fluid-editor/pull/730)). Three were read again and stay ([#727](https://github.com/FRIKKern/fluid-editor/pull/727)). In one, the oracle's block held at phone full width is 376 px wide, and no rule was found for it.
- Gate C is not in CI; it runs only when someone runs it locally ([#731](https://github.com/FRIKKern/fluid-editor/pull/731), [#733](https://github.com/FRIKKern/fluid-editor/pull/733)).
- An outline can still be covered by paint that has no box of its own, such as another element's shadow ([#725](https://github.com/FRIKKern/fluid-editor/pull/725)).
- A full local anim-check was not run for the Float watch change; CI ran it ([#723](https://github.com/FRIKKern/fluid-editor/pull/723)).
