# Fluid editor · Tuesday 17 November 2026

14 pull requests merged. None changed the editor. Eleven made a check harder to fool, two let a check run on a slowed CPU without hanging, and one started this News ([#699](https://github.com/FRIKKern/fluid-editor/pull/699)). A check runs our editor through recorded steps and compares it with what Squarespace's real editor, the oracle, was seen to do. Each of the eleven check fixes proves its point the same way: force a fault on purpose, then show the old check still passes and the new one fails.

## What a person can now do

Nothing new to click today. What changed is how much the checks hold the editor to.

**Undo must undo the page** ([#697](https://github.com/FRIKKern/fluid-editor/pull/697), [#703](https://github.com/FRIKKern/fluid-editor/pull/703)). The rows for "one undo step for a pick" read only whether the Undo button turned off. Now they read the page before the pick, after it and after the undo: the palette pick must change the page and the undo must bring it back exactly. For Base Size, the headline's and the paragraph's text size must go back too, not only the field.

**Panels must open and close** ([#704](https://github.com/FRIKKern/fluid-editor/pull/704), [#696](https://github.com/FRIKKern/fluid-editor/pull/696)). A panel that never closed passed the "opened again" row; now Escape must close it and Edit must open it again. The four "panel stays under" rows never compared the block's top, so an Offset Y that did not move the block passed. Now each step's move is judged against the oracle's, within 2 px.

**Links and text** ([#695](https://github.com/FRIKKern/fluid-editor/pull/695), [#691](https://github.com/FRIKKern/fluid-editor/pull/691), [#692](https://github.com/FRIKKern/fluid-editor/pull/692)). After a Link press, 20 rows wanted the Add Link form but passed when nothing opened. Each now checks the popover is open and shows the form. Four known misses in typing now must keep their markup and a start of the oracle's text, and an undo walk read without its end state fails.

**Resizing** ([#702](https://github.com/FRIKKern/fluid-editor/pull/702), [#698](https://github.com/FRIKKern/fluid-editor/pull/698)). Seven content rows counted as known misses whatever the pull did; now they still must match the oracle's start row and columns. The x6 rows are compared from where the block landed, so a pull before the first read counts.

**Fades** ([#693](https://github.com/FRIKKern/fluid-editor/pull/693), [#701](https://github.com/FRIKKern/fluid-editor/pull/701)). A retried outline fade-out passed if one frame sat on the curve, so a fade that snapped to transparent passed. Now every try must sit on the 0.2 s curve up to its cut, and the cut must come on the 0.2 s timer. That also fails two broken shapes #693's review found still passing: one fade frame and then a snap back to lit, and the outline hidden 1 to 2 frames into the fade.

## Where it is slow or rough

- With `FLUID_CPU_THROTTLE=4`, marks-check runs the page 4 times slower and still matches all 1,729 checks ([#694](https://github.com/FRIKKern/fluid-editor/pull/694)). It is opt-in; CI does not set it. If the throttle's link to Chrome drops, the run now fails at once instead of hanging ([#700](https://github.com/FRIKKern/fluid-editor/pull/700)).
- On Linux CI, marks-check matches 1,724 of 1,729, with 5 font rows named as known misses ([#701](https://github.com/FRIKKern/fluid-editor/pull/701)).

## Where this fits

Milestone M5 on the [roadmap](../ROADMAP.md) is "it looks like the real editor". The checks decide when that is true, so a check that cannot fail makes the "1:1" number too kind. Like Monday, Tuesday added nothing to the editor and turned rows that could not fail into rows that do.
